# 地墙过渡：前足触墙与小幅抬身验证

脚本：`software/scripts/ground_wall_probe.py`。配套模型：`software/hexapod/wall_entry.py`。

提供两种模式：`--self-stand`从地面自行站起、一次验证一只前足；不加该参数则使用承托模式，允许两前足吸墙后进行小幅抬身。都不提供中后足转墙或整机自由翻身。默认只做离线检查；只有`--live`会打开树莓派硬件。离线PASS只代表当前模型和控制流程通过，不代表实物无碰撞或可承重。

## 自行站立模式（无需机身下方垫支撑物）

2026-09-07新增。启动的蹲姿与站姿采用`stand_up.py`相同的地面落足半径130 mm；六足在地面上的指令落点固定，机身髋高从20 mm缓慢升到默认90 mm。默认约11秒。它不是把六只脚在空中收起再踩下；第一拍使能仍与`stand_up.py`一样，发预设蹲姿，不能读取真实关节位置。

1. 将机器人以原来运行`stand_up.py`前的自然趴姿放在平地上，头朝光滑墙面，机身与墙面摆正，前髋轴距墙160 mm。停止其他控制程序、确保没有脚吸住墙面。无需在机身下垫块，首次前足测试保留防跌安全绳，正常时不承重。
2. 先离线运行：

```bash
python3 software/scripts/ground_wall_probe.py --self-stand --mock --demo --report /tmp/wall-entry-self-stand.json
```

3. 实机运行：

```bash
python3 software/scripts/ground_wall_probe.py --live --self-stand
```

4. 输入`start`并回车，等待`SEGMENT complete`，让六足把机身撑起来。
5. 量实际髋轴离地高度与前髋到墙距离。**90 mm是开环运动学目标，没有高度传感器或姿态反馈，吸盘压缩、齿隙和带载挠曲会造成偏差。** 如果实测明显不符，先记录实际值并校正模型/站姿，不要把日志中的90 mm当成实际测量值继续触墙。
6. 一次只测一只前足：`prepare L1` → `touch L1` → 分次`press L1 2` → `attach L1` → `release L1` → `return L1`。每段完成后再发下一条；其他五足保持地面支撑指令。确认L1回地面后才能测试R1。
7. 两只前足都返回且已放气后，输入`sit`，等机身缓慢降到目标20 mm蹲姿；随后`quit`断电退出。

限制：本模式禁止同时把两前足移出地面、禁止地面足压紧/抽气、禁止`pitch`。它依赖现有机器人站立与五足支撑能力，不做吸附足接管重量的验证；五足留在地面是指令约束，没有传感器确认真实载荷或接触。若要验证两前足同时吸墙与抬身，使用下述承托模式。

`stop`和异常冻结不会自动退腿或趴下；先扶稳机身再取机。`quit`/Ctrl-C/EOF仍会断舵机电，若未完成`sit`，机身会失去主动支撑。不能在已经站立/挂墙时重启脚本接管，因为初始化会断电并排气。


## 1. 承托模式的台架与坐标

- 墙面在机头正前方，竖直玻璃或光滑板；地面若要做六足吸附/抬身实验，也要能吸附。无踢脚线、无中间缝隙障碍。
- **整个实验都要有独立机身承托，并沿用安全绳。** 承托须能承受整机重量；抬身测试时允许机身小角度运动，不能把机身刚性夹死后让舵机硬顶。这里尚未求解载荷分配，不可撤去承托来验证自行翻身。
- 默认机身髋轴平面离地 **90 mm**；机身水平时，左右前髋轴到墙 **160 mm**，不是机壳前缘到墙。墙上目标唇口中心离地 **224 mm**；两足目标横向位置分别与各自前髋对齐。
- `start` 的初始停放姿态使用支撑半径约177 mm、足端在髋轴下20 mm；随后慢速伸到地面。上电前承托机身，让腿接近此停放姿态并留出空间：没有舵机位置回读，**首次使能不是从测得的当前姿态插值**。
- **只能从未吸附、卸载的冷启动状态运行。** 驱动初始化会断舵机电；气路初始化会让六足排气。不能在机器人已经挂墙时启动此脚本，也不能与 `climb_walk`、`body_lean` 或语音控制同时运行。

坐标：世界+X朝墙、+Z朝上。`pitch 1` 是机头向上1°，绕机身坐标原点、保持原点高度；不是绕后髋旋转，也不包含身体向墙平移。日志里的足端是自由吸盘模型的**虚拟指令点**，包含压入超程，不是测量出的实际唇口位置。

## 2. 先离线检查

在仓库根目录运行；`python3` 应使用项目已安装依赖的解释器（开发机也可用 `.venv/bin/python`）：

```bash
python3 software/scripts/ground_wall_probe.py --plan --scenario front --report /tmp/wall-entry-front.json
python3 software/scripts/ground_wall_probe.py --mock --demo --scenario mixed --report /tmp/wall-entry-mixed.json
```

第一条检查L1完整触墙、压紧、吸附、释放、回地面的序列。第二条使用理想密封模型，检查两前足上墙、四足地面吸附、抬头1°/2°、回到0°、前足返回。mock里的成功吸附不依赖真实压紧深度，不能用来证明2 mm或18 mm足够。

JSON记录每段指令、六足虚拟目标、压力、泵阀状态、压入量和机身俯仰；拒绝时返回非零退出码及失败指令。调整台架几何后先重跑，例如：

```bash
python3 software/scripts/ground_wall_probe.py --plan --distance 160 --height 220 --report /tmp/wall-entry-220.json
```

所有轨迹使用当前逐舵机标定；检查整段采样轨迹的IK、未截断脉宽（保留50 µs电气余量）、接触时吸盘轴角≤15°、关节中心到地/墙的净空。未检查实体网格、气管、带载变形与真实机械限位。15°是模型门槛，不是本轮重新测得的容差。

## 3. 承托模式的前足触墙：先L1，再R1

树莓派、承托到位后，在终端运行：

```bash
python3 software/scripts/ground_wall_probe.py --live --distance 160 --height 224
```

可用 `--mock` 代替 `--live` 熟悉交互。每条命令按回车；等待 `SEGMENT complete` 或吸附确认后再输入下一条，**不要整段粘贴**。`status` 随时查看压力/状态，`help` 查看帮助。

| 命令 | 动作及观察点 |
|---|---|
| `start` | 发停放姿态、使能舵机、缓慢伸腿至地面；确认承托位置和实体间隙 |
| `prepare L1` | L1抬到离地50 mm，经空中路径移到墙前20 mm；观察大腿、小腿、气管干涉 |
| `touch L1` | 移到模型墙面；检查实际唇口是否接触、是否大致贴正 |
| `press L1 2` | 沿墙法向增加2 mm虚拟压入；必要时逐次重复，默认累计最多18 mm |
| `attach L1` | 抽气；压力连续0.5 s≤−50 kPa才确认。必须已压入至少2 mm；具体需要多少由实测决定 |
| `status` | 查看L1压力、当前压入量、电压、电流、泵阀状态 |
| `release L1` | 承托/卸载后放气；连续0.5 s≥−5 kPa并完成排气状态机才确认 |
| `return L1` | 确认放气后沿法向撤回墙前，再经空中路径返回地面 |

L1通过后，将上述腿名换成R1单独验证。`attach`失败会冻结，没有自动加深、重试或撤腿。冻住后承托取机、退出、调整后重开；不要在仍吸附悬挂的状态重启程序。

压紧动作只在吸附前允许；吸附后不会继续盲目加压。单次压入增量可取0～2 mm之间的正数，总量不超过`--max-press`（允许2～18 mm）。测到实体干涉、持续电流增长、唇边翻折或机身被拉动就停止当前实验，不把继续增加压入当作修复。

## 4. 承托模式的六足混合接触与小幅抬身

前提：前足单独触墙/释放已验证，地面可吸附，承托能跟随机身微小转动。新开一轮：

1. `start`。
2. L1执行 `prepare` → `touch` → 分次`press` → `attach`，保持吸附。
3. R1执行同样的序列，保持吸附。
4. 对L2、L3、R2、R3分别执行分次`press LEG 2` → `attach LEG`。地面足的压紧方向是向下；不要对它们使用`prepare`。一次只处理一只脚，前一只确认后再处理下一只。
5. `status`确认六足吸附。输入`pitch 1`，观察并停留；正常后`pitch 2`。回程依次`pitch 1`、`pitch 0`。

`pitch`是绝对角度，每次变化最多1°，默认范围0～5°（可配置上限最多10°；这只是实验限幅）。整个路径先检查再执行；拒绝则当前姿态不动、不会截断到限位。六足目标点在世界系固定，脚本重新计算各腿角度。固定的是虚拟指令锚点，**不代表实物足端完全不动或载荷已平衡**。

只有两只前足在墙上、四足在地面且六足均通过压力确认才允许`pitch`。回到0°后才允许单足操作。此轮不提供中/后足转墙指令。

## 5. 停止、取机和日志

- `stop`：清空轨迹、停止泵，保留当前阀输出；舵机暂时保持最后指令。进入冻结后不自动恢复，输入`quit`收尾。停泵不能保证长期保压，必须有承托。
- 已吸附足压力回升到−50～−30 kPa：暂停推进，允许补抽；10 s未恢复则冻结。超过−30 kPa：立即冻结。
- 吸附/排气等待最长10 s，吸附状态机本身的抽气超时为2.5 s。传感器异常/读数非法会冻结；不再发送下一帧腿部指令。
- `start`上电完成后，舵机母线低于配置截止线6.0 V，或电流高于配置告警线8 A持续0.3 s：冻结并切舵机电。这里读的是Servo2040母线遥测，不是每个关节的力矩。上电后的检查在发送下一帧运动指令之前执行。
- `release LEG`用于选定足放气，先承托/卸载；有倾角时先正常回到0°。若故障已经冻结，不再允许自动释放或回位，先物理承托取机。
- `quit`、Ctrl-C或终端EOF：停泵、六阀线圈断电、舵机断电。**不自动放气、不自动回位，也不能据此保证仍吸附或保持原姿态。** 承托模式退出前必须独立承托机身；自行站立模式正常结束应先完成`sit`，未趴下或已冻结则先扶稳取机。阀断电为接通真空位置；需要解除吸附时在承托后手动排气。
- 重新运行时气路初始化会排气，所以不能把“重启脚本”当作挂墙续跑。

黑匣子写入 `software/logs/wall_entry_日期_时间.log`，每秒记录六足压力、虚拟目标、俯仰、压入量、泵阀、电压/电流；事件实时落盘。树莓派另启用项目现有PowerWatch电源监测。用`--log-dir`更改目录。

如果旧版在输入`start`之前就报`Battery below cutoff`，是脚本在舵机继电器尚未合闸时也执行了欠压判断；此时母线低电压不能代表电池端欠压。输入`quit`退出，更新脚本及`hexapod/wall_entry.py`后重新启动。修正版在等待`start`时仍读取遥测，但只在上电后启用欠压/过流判断；`status`和日志中的`started`表示启动流程是否完成，并非继电器反馈。若上电后仍报欠压，按报错中的实测母线电压检查电池及供电线路，不能通过调低截止线绕过。

建议拍摄连续侧面视频，画面包括墙角、前足、机身及承托。记录每次实际髋高/墙距、压入量、是否由承托分担重量，避免把“承托下完成”误记成独立过渡成功。后续最有价值的数据是：两前足压紧成功的姿态范围、各阶段电流与掉压、抬头时哪一只脚先倾斜/剥离。
