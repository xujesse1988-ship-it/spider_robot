## 1. 目的与总判据

重跑 08-20 原地踏步实验（同工况同节奏），对照 `--handover` 起标表开/关：

| 指标 | 基线（08-20 实测） | 达标线 |
|---|---|---|
| 每轮下滑（第 2 轮） | 74mm（本管线口径 76.4） | **<10mm/轮**（降一个数量级） |
| vent 跳变逐腿（第 2 轮） | L1 20.9 … L2 5.8mm | **逐腿 \|x\| ≤ 2mm**，无可见弹跳 |
| 整机电流 | 静置 0.79A → 逐周期爬至 ~1.8A 不回落 | **结束静置 ≤ 首抬前 +0.2A**，无逐周期爬升 |
| 交接段身体位移（新增机理检查） | —（基线无此段） | **\|x\| ≤ 3mm 且平滑无台阶**（均值不变的实机验证） |

第 4 条是机构正确性的独立探针：交接期间六腿指令均值不变 ⇒ 身体理应纹丝
不动。若交接段身体系统性下坠 ⇒ 方向/分摊有 bug 或 δ 严重超标，**当场停**。
⚠ 逐腿 δ 表的已知伪迹（设计 §2 ⚠ 注，审核实测）：落地复位吞掉交接残差，
六腿指令均值每次落地跳一步——B 组首轮会累计 ~5mm **上坡**指令伪迹（即首轮
下滑读数比物理真实少 ~5mm）、轮内 ±1.3mm 摆动。这属于表非均匀的几何账，
**不是**分摊 bug：方向是上坡、量有界、第 2 轮起每轮漂移归 0。"当场停"只
认**系统性下坠**；上坡侧的小台阶按伪迹放行。

## 2. 工况与命令行（照抄基线，只差 --handover）

```
# A 组（当日对照，基线复刻）
python scripts/body_lean.py --no-tank --stand-height 62 --tilt-trim 6

# B 组（零力交接，δ 起标表 = 实测弹跳×0.8）
python scripts/body_lean.py --no-tank --stand-height 62 --tilt-trim 6 \
    --handover L1:17,R1:15,L3:11,R3:9,R2:5,L2:5
```

同一面玻璃墙、尽量同一位置；A/B 各自完整"上墙-实验-取下"，中间**不碰相机**。

为什么还要跑 A（08-20 已有基线）：①当日在场对照排除玻璃洁净度/电池/温度
差异；②B 组全程位移 <10mm，**mm/px 比例只能由 A 组的大位移标定**、B 组
沿用（所以相机 A→B 锁死不动是硬要求）；③A 第 2 轮逐腿弹跳若与 08-20 偏差
>20%，δ 表按当日值 ×0.8 重标再跑 B。

## 4. 单组流程（A、B 各跑一遍，动作完全一致）

1. 开录像 → 起脚本 → 缓慢站起 → 就位暂停处检查 → `p` 全吸附启动。
2. **静置 ≥60s**（泵滞环稳定；给 NCC 一段安静漂移参考——基线约 80s）。
3. **对时标记**（新增，A/B 都做）：`↑`×2（+10mm 倾身），等铺完再等 2s，
   `↓`×2 回位，再静置 20s。作用：B 组抬落身体几乎不动，08-20 的"活动对
   比度"对时法会失锁，`ab_quant.py` 自动改用这段大位移锁 off；同时是
   NCC 追踪的现场自检（回放里应看到清晰的一进一出）。
4. **第 1 轮**：按提示轮次逐腿抬落，顺序 **R3→L1→R2→L3→R1→L2**
   （= 基线实际键序 6→1→5→3→4→2；每次"抬落完成，轮到 X"后按对应数字
   再按 `i`，悬停提示出现后再按 `i` 落地）。节奏对齐基线：单腿抬落约
   6s，腿间停 10~15s（等状态行盘压回 -75 泵停再抬下一条）。
   B 组注意：按 `i` 后状态行该腿先显示相位 **Z**（交接 0.5~1.7s）再转
   V——Z 段是新流程正常现象，不是卡死。
5. 轮间静置 ~15s，**第 2 轮**同序重跑。
6. 结束静置 ≥30s（电流回落观测窗）→ 扶稳机身 → `ESC`×2 退出序列 →
   取下机器人。**换 δ 表必须整组重来**（δ 是启动参数，墙上不可改；
   body_lean 退出会放气，必须人扶+安全绳兜底）。
7. 存档：黑匣子 `software/logs/lean_*.log` 拷到 `logs_analysis/`，
   视频拷到 `images/`（命名 `lean_YYYYMMDD_A.mp4` / `_B.mp4`）。

Bash 全部静默失败（本机已踩过）。用 home 下目录，跑完 `rm -r ~/ab/*/seq`

读数位置：分解表"vent跳变"列 = δ 反馈信号（**以第 2 轮为准**）；"交接段"列

## 6. 判定与 δ 修正规则

先看 §1 四条。分支处理：

- **第 1 轮早腿轻微上弹（-1~-3mm）= 预期，不动 δ**。1-D 模型：交接稳态
  下每次抬腿的储能与基线稳态相等（δ 按基线弹跳标对稳态是对的），但首轮
  储能从 mg/6k 爬坡到稳态（模型 14.8→36.9，基线实测 vent 跳变第 1 轮
  2.3→16.3mm 同款斜坡）——首轮早腿必然轻度过冲。**判定一律看第 2 轮**。
  另：逐腿 δ 表的落地复位伪迹（§1 判据 4 ⚠ 注）会让 B 首轮下滑读数比物理
  真实**少 ~5mm**——首轮数字偏好看属预期，同样不作数。
- **交接被引擎截断的抬落不进 δ 修正**：脚本打出"⚠ 交接越界截断"（黑匣子
  同记）说明该次 δ 没铺满、弹跳必然偏大——那是工作空间账（步幅/漂移）的
  问题不是 δ 不够，按残余加 δ 会火上浇油。有效 A/B 组内截断次数应为 0，
  出现即先查步幅/站位再重跑该组。
- 第 2 轮某腿残余下坠 >3mm：δ_i ← min(δ_i + 0.8×残余/|斜率_i|, 45)。
  斜率_i 取该腿"弹跳 vs δ"实测斜率（08-24：L1 0.57/R1 0.39/L3 0.21/
  R3 0.25/R2 0.13/L2 0.14）；没有斜率数据时保守用 0.8×残余×5（均匀刚度
  近似）。旧钳位 21 是"弹跳当储能"的错账（设计 §5 ⚠），已随解析上限
  25→45 一并废止；
- 第 2 轮某腿上弹 <-2mm：δ_i ← δ_i − 0.8×|上弹|；
- 改表后整组重跑 B'（重新上墙）；一个下午预算 A + B + B' 三组
  （每组墙上 ~10min + 换装 ~3min）。
- **当场停**的情形：交接段身体系统性下坠（机理 bug，回桌复查 4.7 步方向
  /分摊）；任一腿上弹 >5mm（δ 严重超标，全表减半重试）；第 1 轮下滑
  不降反升（方向反了级别的错误）。
- 冻结处理照旧：交接中支撑腿**或交接腿本身**漏气都会自动暂停（v1.6 起
  交接腿纳入监护；Z 段变长属正常），挽救超时冻结按 `f` 续铺；
  `clear_freeze` 不丢在途交接（tests §7.6 已固化）。

达标后的推进（设计 §9.4）：climb_walk 先单步（`i`）后连续，δ 微调，重测
净前进率（26% 基线）——ab_quant 现已直接解析 climb_walk 日志（单步/连续
混跑都行，从相位转移行建时间线；退出序列的放气会被滤掉不计入抬落——
08-19 climb 日志真实抬落是 10 次，按 vent 事件数数出的 16 是错的）；
δ 标稳后可另开一组 `--handover-weights`（载荷按窗序
轮转距离加权，设计 §5 v1.5；口径假设按"轮到 X"提示轮转抬腿）A/B——模型预期循环内应力降 ~30%、δ 表随之整体
下调重标，务必与 δ 标定分开成组，别混变量；报告并入 html（管线输出直接喂
`vent-snap-20260820.html` 同款图表）。**A/B 期间 --sag-comp 保持 0**
（两者同开双份推挤支撑系，设计 §4.3）。
