下面按"先物理、后数学、最后电气"的顺序,把每一环拆开讲。

1. 硬件:一条腿的三个关节(动手转转看)

每条腿 3 个舵机、3 段连杆,从身体往外依次是:

关节俗名转轴方向干什么代码符号连杆长
coxa髋竖直(垂直于吸附面)整条腿在水平面里前后扫γ(gamma),0=腿的中性朝向43 mm
femur大腿水平腿在竖直面里抬起/放下α(alpha),水平=0,抬起为正81 mm
tibia小腿/膝水平膝盖屈伸,决定脚离髋多远θ(theta)=大小腿夹角,伸直=180°123.7 mm

直觉版:coxa 管前后,femur 管高低,femur+tibia 一起管远近。 走路时脚要沿直线匀速移动,而三个关节都是转的——所以三个角必须同时按曲线变化, 互相配合才能"转出直线"。这正是为什么需要每帧重算(第 5 节的逆运动学)。

六条腿的编号与朝向:左侧从前到后 L1/L2/L3,右侧 R1/R2/R3。 每条腿有个"中性朝向"(装配决定,如 L1 朝前外侧 55°、L2 朝正左 90°), γ=0 就是指着这个方向。后面所有"腿坐标系"的计算,x 轴都沿着各自的中性朝向—— 这样六条腿能共用同一套 IK 公式。

2. 走路的本质:支撑相与摆动相

六条腿永远轮流处在两种角色里:支撑相(吸住,当"地面",把身体送过去)和 摆动相(松开,去前面找新落点)。看懂走路只需要三步:先统一视角(2.1), 再看支撑的腿怎么送身体(2.2),最后看排班表怎么排(2.3)。换脚动作本身的细节留到第 3 章。

2.1 先统一视角,不然怎么看都乱

  • 墙面系(现实):吸住的脚钉在墙上,一毫米不动;支撑腿的关节慢慢转,身体被平移过去。 不是脚蹬墙,是身体爬过脚。
  • 身体系(代码):身体永远在原点。"身体以 13mm/s 前进"这句话,记在账上就变成 "每只支撑脚的目标点以 13mm/s 向后移动"。

这两句是同一件事,只差一个坐标系。检验自己有没有看懂的标准,是能不能接受这句话: "支撑脚的目标每帧都在动,但脚本身在墙上一毫米都没动。" 目标动掉的那部分,恰好全部变成了身体的前进。

为什么代码选身体系记账?因为下一环节 IK 要回答的就是 "脚相对身体在哪"(第 5 节)——身体系记完账直接送进 IK,墙面系反而每帧要多换算一次。 代价是初看代码容易被"支撑脚在后退"绕晕:它退的是账,不是墙上的脚。

2.2 支撑相:身体不是被"蹬"前进的

五条腿吸住时,它们的 15 个舵机并没有闲着——每帧都在按 IK 重算的角度缓慢协调地转, 把身体从脚上方匀速平移过去。没有蹬踏、没有发力瞬间,是纯位置控制的几何搬运。 数字感受一下:满速 13.3mm/s 时,一帧(20ms)身体只挪 0.27mm—— 肉眼看是连续滑动,舵机眼里是一串微小的位置修正。

单看一条腿的一生,它像一节短滑轨上的滑块(步幅 40mm 为例):

换脚落点:选在站位前方 +20mm(半步幅)
   ↓ 吸住。身体前进,它在身体系里匀速向后"滑"
经过站位 0
   ↓ 继续滑
滑到站位后方约 −20mm ←— 正好轮到它的换脚窗口:起脚,再落回前方 +20,循环

还有一条硬约束,解释了引擎里很多看似绕的设计:吸住的脚在墙面上绝对不能滑 (滑动=蹭破密封=掉落风险)。所以支撑目标必须与身体运动严格互补、连续积分—— 速度指令突变,目标位置也不跳变;而所有"暂停"(钟停、漏气挽救、冻结)的实现方式 都是同一个动作:把支撑目标原地冻住。

2.3 排班表:步态 = 谁在什么时刻换脚

三个术语,后面到处要用:周期 T(爬墙 3.6s)、duty(支撑相占周期的比例,爬墙 5/6)、 窗口(每条腿在周期里分到的换脚时段,T×(1−duty)=0.6s)。 把六条腿的窗口画在一张图上,"步态"这个词就具体了——它就是一张排班表:

  • 为什么爬墙一次只挪一条腿:5 个吸盘扛整机是安全底线。窗头还有两道关卡: 互锁(其余 5 脚必须全部 ATTACHED)和抬腿门槛(所有支撑盘压深于 −50kPa—— 刚吸上的邻腿是"软肩膀",立刻抬下一条会压垮它),不满足就停在窗头等。
  • 为什么顺序是 R3→L1→R2→L3→R1→L2:相邻两次抬腿全在对角/交叉位,扰动分散两侧。 旧顺序左三连再右三连,半个周期的扰动集中在一侧——08-19 实测 R2/R3 抬腿整机下坠的结构性根源。
  • 钟时间 vs 真实时间:身体只在钟走时前进。每个窗口 = 钟走 0.6s、然后停 ≈3.5s 等换脚的腿收口。真机"走一小段、停一会儿、再走一小段",就是这张排班表叠加钟停规则的 直接结果,不是卡顿。

两张排班表的参数对比:

3. 爬墙摆动相:一只脚换位的六段状态机

地面步态的摆动就是"抬起-前挪-放下"一条正弦弧线。爬墙不行:吸盘的释放和密封 都有物理过程,拍地、拖脚、带真空硬拔都会出事。所以 climb.py 把摆动拆成状态机, 每段只干一件事:

段干什么为什么必须有这段(都是实爬教训)
VENT 0.3s原地不动,只开排气阀边放气边抬,排气建立比抬离慢,腿会被残余真空"拽起"(08-19 实机)
LIFT ≈0.83s从压入位 −18 沿墙法向拔出、退到面上 +15,总行程 33mm(40mm/s)吸盘自身回弹 11~13mm,退少了脚还蹭在墙上。相位钟在 LIFT 进行 0.3s 时到窗尾停住(此刻脚还在面下 −6mm)——支撑腿比摆动脚离面更早冻结
TRANSFER 0.6s平移到落点正上方(smoothstep 平滑)先到"正上方"再下,落地才没有横向速度,不拖脚
DESCEND竖直慢速下探(30mm/s),XY 冻结消灭"拍地"——撞上去的瞬间速度会破坏密封
PRESS继续压入 18mm(15mm/s)波纹盘要压扁才密封;13mm 被腿链让位吃掉大半,实测加深到 18
WAIT抽气,等盘压过 -30kPa 确认吸牢吸不牢就回抬 5mm、比上次再深压 5mm 重试(原深度重压必然同败),3 次失败全机冻结报警
相位钟会在这些地方暂停(你日志里各种"等"的来源): ① 窗尾摆动腿还没吸牢——钟停,全身冻结等它; ② 窗头互锁:其余 5 脚没全部 ATTACHED 不准抬; ③ 窗头门槛:有支撑盘压还浅于 -50kPa(刚吸上的邻腿是"软肩膀"),等泵拽深,超 15s 报警; ④ 任一支撑脚漏气——2s 挽救窗内钟暂停,超时冻结。 这套"能停的钟"就是 climb 引擎和 P3 纯开环步态的本质区别。

4. 支撑相的数学:每帧挪 0.3 毫米

速度指令怎么变成支撑脚的目标?三步(gait.py):

① 步幅向量 u = 速度 × 支撑时长        (爬墙:T_stance = 3.6s × 5/6 = 3s)
   例:vx=13mm/s 直行 → u ≈ 40mm(正好是爬墙单步上限 climb_max_step)

② 转向时每条腿的 u 不一样:u = (v + ω×r) × T_stance
   ——刚体速度场:离转轴远的腿要走更长的弧,原地转时六条腿的 u 方向各不相同

③ 支撑相内,目标从 站位+u/2 匀速滑到 站位−u/2:
   target = 站位 + u × (0.5 − 相位进度)

在 50Hz 循环里,15mm/s 的速度意味着每帧目标只挪 0.3mm。 舵机收到的是一串间隔极小的位置指令,看起来就是连续运动。 "走路"在舵机眼里,只是 1500µs → 1499.7µs → 1499.4µs…这样的脉宽微调流。

5. 逆运动学:从"脚该在哪"到三个关节角

现在每条腿有了一个目标点(身体系)。变成角度分两步走(robot.py → kinematics.py):

第一步:换到腿自己的坐标系

身体系 (X,Y,Z)
  → 减去该腿髋轴的安装位置 (mount_x, mount_y)     # 如 L2 装在 (0, 81.5)
  → 反转该腿的中性朝向角 mount_angle              # 如 L2 转 −90°
  → 得腿系 (x,y,z):x 沿腿中性朝外,z 向上

(若爬墙时身体还有姿态微调 body_shift / 俯仰滚转,先做一次逆变换,同在此步。)

第二步:三个角,两道几何题

γ = atan2(y, x)                       # 俯视方位角,coxa 直接对准目标
r = √(x²+y²) − 43                     # 减掉 coxa 平段,剩下二连杆问题
d = √(r²+z²)                          # 髋(femur轴)到脚的直线距离

θ = acos( (81² + 123.7² − d²) / (2·81·123.7) )      # 三角形顶角=膝角
α = atan2(z,r) + acos( (81² + d² − 123.7²) / (2·81·d) )  # 视线角+抬角
WorkspaceError 从哪来:三角形要成立,必须 42.7 mm < d < 204.7 mm(两杆长之差与之和)。目标太远/太近,余弦定理里的 acos 就无解——代码抛 WorkspaceError,爬墙脚本捕获后全机冻结悬停(双降落伞之一)。 climb.py 里各种"离包络留 3mm 余量""补偿尾预算"的账,全是在保证支撑目标 被身体运动越拖越远时,永远到不了 d=204.7 这堵墙。

膝盖有"内扣/外翻"两个镜像解,公式固定取一支(你的装配方向); IK 每帧独立重算,同一目标永远得同一组角,所以不会"跳解"。

6. 标定表:从关节角到脉宽 µs

舵机不认识"度"。它只认脉宽:每 20ms 给它一个 500~2500µs 的高电平脉冲, 脉冲多宽,舵盘停在哪个角,内部电位器自己闭环。所以最后一步是查每个舵机的标定表 (config.py 里 18 份 ServoCal,2026-08-08 全部实测拟合):

servo_deg = sign × (关节角 − attach_deg)          # 先换算成"舵机自己的度数"
us = 1500附近的中点 + servo_deg × (us_p45 − us_m45) / 90   # 线性映射,再夹到 500~2500

三个容易迷糊的点:

  • attach_deg(零位偏置):舵盘是花键插上去的,插的位置决定"舵机中位=关节几度"。 官方给设计值(coxa −8°/femur 35°/tibia 68°),你的表里是逐个实测值(如 L2 femur 47.81°)。
  • 左右镜像:右腿是左腿的镜像装配,femur/tibia 舵机转向与关节约定相反—— 不改公式,把 ±45° 两个脉宽对调就行(表里 R 腿是 1045/1955,L 腿是 1955/1045)。
  • 膝关节送的不是 θ:标定表用弯曲角 k = 180° − θ(伸直=0), 所以代码里是 tibia.joint_deg_to_us(180 − θ)。

完整算例:L2 腿站姿(每个数都可在真机复现)

7. 最后一跳:串口包与 PWM

18 个脉宽算好后,树莓派把它们打成一个串口包发给 Servo2040 驱动板:

Servo2040 收到后,把 18 路 PWM 引脚的脉宽寄存器一改,硬件持续输出。 每个舵机拿到自己的脉冲,内部电位器+电机自成闭环转到目标角。 两个 50Hz 是巧合但独立:控制循环 50Hz 是软件节拍,PWM 50Hz 是舵机信号规范。

全链路最重要的一个坑:开环。 舵机没有位置回读——树莓派只知道"脉宽发出去了",不知道关节真转到没有。 带载时齿隙+结构弹性会让实际角度差出去,足端差好几毫米: 这就是 08-19 视频里 press 反力把支撑腿链压弯 13~27mm、 press_delta 名义 13mm 实际只压进几毫米要加深到 18 的物理根源。 代码里所有"实测回填""判据靠气压/电流不靠指令位置"的做法,都是在绕开这个盲区。 (气路那边有反馈:盘压传感器 → -30kPa 吸牢判据 → 才敢抬下一条腿。 运动是开环的,吸附是闭环的,爬墙的安全全押在后者。)

8. 收个尾:一帧(20ms)里到底发生了什么

1. 读键盘:得到速度指令 (vx, vy, wz)
2. eng.update(dt, vx, vy, wz)                        # climb.py
   ├ 相位钟推进(或因互锁/门槛/未吸牢/漏气而暂停)
   ├ 摆动腿:按状态机(VENT→…→WAIT)算本帧位置,驱动气阀
   └ 支撑腿:目标反向平移 v·dt(≈0.3mm),含下滑补偿
   → 返回 6 个足端目标(身体系)
3. bot.move_feet(targets)                            # robot.py
   ├ 每腿:身体系→腿系(减安装位、转中性角)
   ├ 每腿:leg_ik → γ, α, θ                          # kinematics.py
   ├ 每关节:标定表 joint_deg_to_us → 脉宽            # config.py
   └ 18 路脉宽按通道号排好
4. driver.set_all_pulses_us(...)                     # driver.py
   → 0xD3 串口包 → Servo2040 → 18 路 PWM → 舵机转动
5. 另一线程/节拍:气路状态机 ctl.update(dt) 管阀和泵,读盘压
6. sleep 到下一个 20ms
