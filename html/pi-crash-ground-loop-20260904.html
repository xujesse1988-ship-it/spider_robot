合闸瞬间的地环路

树莓派 5 在舵机继电器合闸的一瞬间概率性断电死机。三天里从"阀线圈"查到"5V 余量"，再查到"18 舵机大电流"，最后被一张 14 毫秒的日志和一根 USB 线定案。这份案卷记下走过的弯路、真正起作用的工具，和可以带到下一个项目的经验。

机器：Pi 5 + Servo2040 + 18 舵机 + 六阀 供电：2S 锂电 → 5V 降压给 Pi；继电器切舵机正极 症状：状态灯绿 → 红常亮，SSH 失联，需重新上电
根因
继电器合闸时的充电脉冲经 USB 地线灌进 Pi，PMIC 判欠压断电
定案证据
同一次开机只拔一根 USB 线：拔掉合闸十次 0x0，插回第一次 0x50000
治法
USB 隔离器；舵机轨预充软启动；星形接地
01

症状与约束

启动脚本先把六个电磁阀线圈逐一通电到排气位，然后合舵机继电器。有一定概率就在这段时间里树莓派整机死掉：红灯常亮、绿灯熄灭、SSH 连不上，只能断电重来。Pi 5 的这个灯态是 PMIC 把处理器断电后的停机态，和 sudo halt 之后一样。

手上没有示波器。能用的只有万用表、Pi 自己的 PMIC 读数接口（vcgencmd pmic_read_adc，实际能跑到 10 Hz）和内核日志。死机是断电式的，死的瞬间没有任何进程能再写盘，所以一切都要"死前留痕"。

02

为此做的工具

黑匣子

每个大电流步骤（每路阀线圈通电、继电器合闸、固件使能）之前先写一行并 fsync，日志停在哪一行，凶手就是它的下一步。后台线程每 0.1 s 记一行 Pi 的 5V 输入电压和欠压标志，每行落盘。合闸后 0.05 / 0.15 / 0.30 s 再补采舵机母线电压电流。四个启动脚本同口径，日志落在 software/logs/<tag>_时间.log。

验尸脚本

scripts/pi_forensics.sh setup 把内核日志改成持久化、每秒同步，必须在死机之前跑一次。重新上电后 check 一次带出：上次开机的内核尾巴、真实开机时刻（Pi 5 没有 RTC 电池，开机列表里的时间是上次存盘的假时钟）、当前欠压标志与 PMIC 电压、固件电源节点、最新一份黑匣子尾巴。

看懂两个只读接口

接口值含义
get_throttledbit 0 / bit 2此刻欠压 / 此刻限频。瞬态过去就清零
get_throttledbit 16 / bit 18本次开机曾欠压 / 曾限频。粘滞位，重启才清。PMIC 快速比较器锁存，比 ADC 采样快得多
chosen/power/power_reset2树莓派工程师 timg236 论坛原话：非零（通常 2）表示上次开机是 PMIC 因输入电压过低断电。两次死机后读到的都是 2。09-06 更正：正常 poweroff/reboot 几次之后仍读 2，本机上它没有区分力，已从证据里撤下（见 07 节）
03

排查经过

  • 09-02报告：阀线圈逐一亮起之后死机。第一嫌疑是阀。给启动加逐步落盘和 --startup-gap，准备把阀和舵机隔开定位。
  • 09-03第一次验尸：六路线圈通电全程 5V 平稳 4.88 V，"继电器已合闸"是最后一行，50 ms 内死。阀无辜，扳机是合闸。当时把根因押在"5V 空载只有 4.89 V 余量太薄"上，同时把合闸拆成"合继电器 → 0.4 s → 固件使能"两步，让黑匣子能分清带电冲击和出力冲击。
  • 09-04 下午换成可调降压模块，调到 5.19 V，PMIC 读 5.105 V。跑 walk_teleop 仍然死机。静态电压不是根因。这次 walk_teleop 没接黑匣子，只能空手验尸；journal 在开机 301 s 后戛然而止、没有任何欠压字样。补齐 walk / voice 两个脚本的黑匣子。
  • 09-04 晚用户发现：开机 0x0，跑一次 walk_teleop 没死，标志却变成 0x50000。每次合闸都欠压，只是有时跌得不够深。偶发的致命事件有了一个确定的、非致命的替身。
  • 21:54关键日志：合闸后 14 ms 标志置位，此时舵机母线 0.00 A。不是"18 舵机抽垮电池"。之后使能瞬间 6.67 A、电池掉 0.4 V，Pi 的 5V 纹丝不动。
  • 22:xxA/B：拔掉 Pi 到 Servo2040 的 USB 线只合闸，十次 0x0；插回，第一次 0x50000。路径定案。降压模块的指示灯在合闸瞬间闪绿，是模块自己看见了同一股脉冲。

05

A/B 实验

同一次开机，同一段程序，只碰 GPIO17：合闸 0.2 s 后读标志，停 2 s，断开，停 2 s，重复十次。不开串口，不碰阀，舵机带电但没有 PWM 不出力。唯一变量是 Pi 与 Servo2040 之间的 USB 线。

拔掉 USB 线

10 / 10 → 0x0

合闸十次，粘滞位一次都没置。

插回 USB 线

第 1 次 → 0x50000

第一次合闸就置位，之后九次一直是。

没有第二种解释：脉冲进 Pi 的路径就是这根 USB 线的地。

import subprocess, time, lgpio
h = lgpio.gpiochip_open(4)          # Pi 5 主 gpiochip（新内核为 0）
lgpio.gpio_claim_output(h, 17, 0)   # GPIO17 = 继电器 IN1
def thr(): return subprocess.run(["vcgencmd","get_throttled"], capture_output=True, text=True).stdout.strip()
print("合闸前", thr())
for i in range(10):
    lgpio.gpio_write(h, 17, 1); time.sleep(0.2); print(f"第 {i+1} 次合闸后 {thr()}", flush=True)
    time.sleep(2); lgpio.gpio_write(h, 17, 0); time.sleep(2)
06

脉冲走的路

降压模块的绿灯是旁证

新换的模块是 XL4015 5A 恒流恒压板，背面丝印写着红灯恒流、蓝灯充电、绿灯充满。检流电阻 R10 是 50 mΩ，串在 OUT− 和 IN− 之间，也就是 Pi 的地和电池负极之间；输出电压按 IN− 调节，任何流过它的电流都直接从 Pi 看到的 5V 里扣掉。合闸瞬间蓝灯闪绿，是电流比较器看见输出电流一下子掉到近零甚至反向，只可能是外来脉冲穿过了它。旧的固定 5V 模块没有这只电阻也死机，所以它不是根因，只是把跌落再放大了一截。

线索为什么像怎么排除的

08

结论与治法

根因是继电器合闸瞬间对舵机侧电容充电的脉冲，经 Pi 与 Servo2040 之间的 USB 地线灌进树莓派，在 GND 杜邦线和检流电阻上产生的压降被 PMIC 判为输入欠压。跌得浅时只留一个粘滞位，跌得深时 PMIC 直接断电，表现为红灯常亮。

  1. USB 隔离器。ADuM3160 一类的全速隔离器，12 Mbps 够 Servo2040 的串口，插在 Pi 和 Servo2040 之间，地环路物理断开。最干净的一刀。
  2. 舵机轨预充软启动。第二只小继电器串 4.7 Ω 5 W 电阻先合 100 ms 把电容充到位，再合主继电器；或换 P-MOS 软启动模块。先用 10 Ω 电阻跨触点手动预充一秒再合闸、看粘滞位，即可验证。
  3. 星形接地。Servo2040 的 GND 和降压模块的 IN− 各自短粗线直接压到电池负极同一点；Pi 的 5V/GND 不用杜邦线。只能减轻，不能断路径。

Pi 5V 针脚上并电容只治标：按 Pi 5 约 0.7 A 算，2200 µF 只能把 0.4 V 的跌落撑约 1 ms。XL4015 的 R050 可以用焊锡短接让 OUT− 直接等于 IN−，模块退化成纯稳压，指示灯失效无妨；路径断掉之后它本身无害，可以不动。

软件层已经到位：合闸拆两步、四个启动脚本同口径的黑匣子、验尸脚本的真实时间线和 power_reset 释义。--startup-gap 已无必要。

09

可以带走的经验

断电式死亡只能死前留痕

每个大电流步骤之前写一行并 fsync，日志停在哪一行，凶手就是它的下一步。没有这一行，三天的排查一步都走不动。

给偶发的致命事件找一个确定的替身

粘滞位每次合闸必置，不需要等死机。实验判据从"死不死"换成"置不置"，一次重启就有结论，"没死"也不再是无信息。

点采样看不见瞬态

ADC 读 5.105 V 的同一拍，快速比较器已经锁存了欠压。万用表和 10 Hz 采样对百微秒的事件是盲的，别用它们的"正常"否定故障。

大电流不等于问题，开关瞬间才是

6.67 A 的持续冲击 Pi 毫无反应；0 A 时的合闸却每次欠压。看的是 di/dt 和电流走哪条路，不是安培数。

地不是一个点

USB 线、检流电阻、杜邦线各自都是地回路里的电阻。两块板共地又各自回电池，脉冲就会挑一条你没想到的路。

一次只变一个变量，同一次开机

拔一根线、十次合闸、插回、再合，结果 0x0 与 0x50000 对照，不留任何解释空间。比换模块快，也比换模块便宜。

厂家的一句话也要做对照

power_reset=2 在论坛上有原话背书，两次死机后都读到，当时当成 PMIC 的口供。09-06 正常关机后再读，还是 2。没有对照组的读数不是证据。

换零件之前先量证据

换降压模块只证明了"静态电压不是根因"，这个结论值，但如果先看粘滞位，本可以不花这一步。
