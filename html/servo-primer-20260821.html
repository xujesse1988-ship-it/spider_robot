舵机手册

这台机器有 18 个舵机，是全机数量最多、最贵、也最容易被误解的零件。 它不是"电机"——你不给它电压，你给它一个角度；它内部自己闭环转过去。 但这个闭环关在壳子里，外面拿不到位置：程序永远只知道"指令发出去了"， 不知道关节真的转到没有。爬墙时踩过的坑，大半从这一句话长出来。

1壳子里面是什么

一个标准舵机 = 小直流电机 + 减速齿轮组 + 位置电位器 + 一块控制板，塞进一个小盒子， 引出三根线：电源正、地、信号。控制板不断比较"信号线要求的角度"和"电位器测到的实际角度"， 差多少就驱动电机往哪边转，转到差不多就停——这是一个完整的位置闭环，只是它在盒子里面。

橙色是命令流，蓝色虚线是反馈流。反馈流不出壳——这一张图解释了本项目后面一半的设计取舍。

和别的"会转的东西"区别在哪

类型你给它什么它给你什么适合做什么
直流电机电压 / 电流转速，位置得自己加编码器轮子、泵、风扇
步进电机一步一步的脉冲开环角度，丢步不告诉你3D 打印机、机床
PWM 舵机目标角度（脉宽）只有转动，没有任何回读关节、舵面、这台机器
总线舵机目标角度 + 速度 + 力矩上限能读回位置、电流、温度要力控或诊断的关节

本项目用的是第三种。舵机自己内部还分好几个大类（模拟 / 数字 / 总线 / 关节模组， 以及限位、连续旋转、多圈三种转法），放在第 3 节展开； 换成别的类型对这台机器意味着什么，放在第 10 节算账。

2它怎么听懂"角度"

信号线上是一串方波：每 20 毫秒来一个高电平脉冲，脉冲多宽，舵盘停在哪。 行业惯例 1500µs 是中位，1000/2000µs 是常见的两端；本项目把范围放宽到 500~2500µs 用满行程，实测斜率约 10µs = 1°。 脉冲之间的 20ms 空档不代表"松开"——只要脉冲不断，舵机就一直用力顶在那个角度上。

关节角一栏用的是 L2 大腿舵机（通道 10）的实测标定：attach = 47.81°（中位时关节实际就在 47.8°， 不是 0°）、舵机自身 ∓45° = 1952.5 / 1047.5 µs。 这一路脉宽变大关节角反而变小——左右腿是镜像装配，方向差不改公式，直接收进标定表的两个端点里。 换一个舵机，同一个脉宽对应的关节角就完全不同，这就是 18 路必须逐个标定的原因。 另外滑块给的 500~2500µs 是软件软限位，真实机械行程比这窄，超出会撞结构——代码里另有关节角包络检查兜着。

数字舵机和模拟舵机

差别不在信号（都吃同样的脉宽），在内部：模拟舵机大约按 50Hz 的节奏驱动电机，死区大、抖、保持力弱； 数字舵机内部以几百 Hz 驱动，死区小、响应快、保持扭矩明显更高，代价是更费电、更热。 做关节必须用数字舵机——爬墙时每条支撑腿都在持续扛剪切力，靠的就是这份保持扭矩。

3舵机的几个大类

先分清两个撞名的"伺服"

中文里"伺服电机"和"舵机"经常混着说，但搜出来是两个世界：

  • RC 舵机（本页说的这种）：电机、齿轮、反馈、驱动全塞进一个小盒子，引出三根线，几十到几百块。
  • 工业伺服：无刷电机 + 编码器 + 一个单独的驱动器，闭环在驱动器里，接口是脉冲串、EtherCAT 或 CANopen，一套几千起，体积重量都不是 DIY 机器人扛得动的。

找资料时用"舵机"或 RC servo，别用"伺服电机"——会跑到完全不相干的行业里去。

  • 微型（9g 级）：SG90 那种，几块钱一个，塑料齿，扭矩 1~2kg·cm。做摄像头云台、玩具够用。

5力矩够不够：只能靠电流看

舵机不告诉你它在使多大劲，但电流会。这是本项目唯一能"看见力"的窗口， 所以驱动板的电流读数从头到尾都在状态行里显示。

本项目实测

单腿压紧峰值 0.73A；吸附后挂重保持期 持续 0.61A 扛载。

整机行走 持续 2~4A、瞬态约 12A——这个数决定了舵机总电源开关要选 ≥15A 的继电器。

墙上五足支撑是持续承剪切载荷，也就是持续 3A 级电流 + 持续发热。这是常态，不是异常。

三条用电流做的判据

  • 吸附后总电流要回落到该姿态的基线。不回落 = 这条腿的预压量没吃干净，舵机正在和真空对抗——白烧电、白发热。
  • 电流逐周期爬升不回落 = 内应力在累积。08-20 实测整机从 0.73A 一路爬到约 1.9A，这是"弹性棘轮"的电学证据。
  • 压入时电流陡增但还没到预期高度 = 撞到东西了，立刻停。

6舵机不老实：五种带载行为

以下五条在数据手册上一条都找不到，但每一条都在这个项目里造成过实际后果。 它们的共同根源就是第 1 节那张图：你发的是位置，收到的是"大概那个位置"，而且你无从知道差多少。

一 · 让位角：带载时它停不到指令位置

电机的保持力矩是有限的，外力越大，实际停的角度离指令越远——像一根很硬的弹簧，不是刚体。 本项目里这一条最贵的一次表现：足端预压行程按几何算是 13mm，实机发下去只压进几毫米， 大半被"舵机带载位置误差 + 齿隙"吃掉了，最后默认值改成 press_delta_mm = 18， 用指令超程换真实压缩。

二 · 齿隙：反向时先空转一点

金属齿轮组必然有间隙。同一个目标角，从上面过去和从下面过去，实际停的位置不一样。这让"回到原位"这件事天然不精确。

三 · 扭矩饱和：储能有上限

实测单腿抬起时的弹性回弹最大约 21mm 就封顶了，再抬也不会更多——因为舵机扭矩到顶，存不进更多能量。 这条既是坏消息（说明腿链一直在被压弯），也是好消息（棘轮效应有天花板，机器不会无限往下掉）。

四 · 它是弹簧，会存能量

舵机让位角 + 吸盘的橡胶变形 = 一根串联弹簧。抬腿前这根弹簧一直在存能， 吸盘密封破裂的一瞬间一次性释放——实测 83% 的整机下滑就发生在那 1~2 帧里。 解法不是让舵机更硬，是放气前先把这条腿的载荷交给其他五条，让弹簧里没有能量可放。

五 · 发热与降额

持续扛载的舵机会烫。判断有没有超出安全区的土办法：加深 3mm 预压后电流增幅仍平缓、 没有陡增、没有异响、摸着不烫手，就认为有余量；陡增就是已经贴近堵转区了。

一条铁律：使能状态下永远不许用手掰关节。 35kg·cm 的堵转力矩足够打坏齿轮，而且掰出来的角度是假的——松手它就自己转回指令位置。 要调整姿势，先断舵机电。

7装配与标定：装不准是常态

舵盘是花键插在输出轴上的。本项目的舵机是 25 齿花键， 也就是 360 ÷ 25 = 14.4° 一格——舵盘只能插在这些离散角度上， 最坏情况会差 ±7.2°。所以官方给的安装角（−8° / 35° / 68°）是设计意图，不是公差要求， 对不准是正常的，不用拆了重装。

正确做法是三步：

  1. 先回中再装舵盘：上电让全部舵机停在 1500µs，保持通电状态把舵盘按最接近的一格插上（servo_center.py）。
  2. 实测两个点：把关节摆到 −45° 和 +45°，记下对应脉宽。
  3. 把残差写进标定表：attach_deg 记"舵机中位时关节实际是几度"，方向反了改 sign。18 个舵机各一份。
这一步有多费事

18 路标定是整个装配阶段最耗时的工序，本项目花了好几天，还专门写了一个最小二乘拟合脚本 （calib_fit.py）：每个舵机测 2~4 个点，拟合出斜率和零位，看残差判合格。 标定表的完整算法和一个可复现的算例，在《从走路指令到 18 路舵机》那份图解里。

一个值得认识的故障：舵盘滑丝

症状是"这个关节的回中角度自己变了"。原因是舵盘花键孔被磨圆，和输出轴打滑。 换舵盘即可，但换完必须重标定这一路——attach_deg 已经不是原来的值了。

8供电、上电顺序与断电行为

绝不和控制器共用电源轨

18 个舵机同时动，瞬态能拉到 12A，电压会明显往下掉。 如果树莓派和舵机吃同一路电，舵机堵转的一瞬间树莓派就重启——在墙上重启等于掉下来。 本项目的做法：2S 电池直供舵机，另接一路独立的 5V/5A 降压给树莓派，两路只共地。

上电顺序：先发脉宽，再使能

舵机上电瞬间会直接冲向信号线要求的位置。所以正确顺序是 先把 18 路目标脉宽发好，再合舵机电——固件保证使能瞬间直接到位，不乱跳。 整机上电还要多一步：先发蹲姿（离断电趴姿最近，跳变最小），再缓慢过渡到站姿。

断电 = 趴下，这是特性不是故障

舵机没电就没有保持力，机器人会瘫成一堆。本项目把这一点当成急停机制来用： 舵机总电走一个由树莓派控制的继电器，脚本正常退出、异常崩溃、甚至进程被强杀， GPIO 一释放继电器就断开，舵机立刻失电。

但爬墙时"趴下"是不够的。所以吸附回路做成了断电保持真空：舵机断电机器人软下来， 六个吸盘仍然吸在墙上不掉。两套断电行为是分开设计的——这是整机安全论证里最关键的一条。

另外软件里设了两道电压线：6.4V 警告、6.0V 直接抛异常停机。 锂电欠压意味着泵没力、舵机没劲，在墙上就是掉落前兆。

9三张自检清单

到手三查

  • 标签电压是否含 7.4V（不是 6.8V 上限版）
  • 控制角是 180° 而不是 270°
  • 金属齿、附舵盘和螺丝
  • 逐个单独上电扫一遍 1000→2000µs，听有无异响、看有无卡顿

装配前

  • 先回中到 1500µs 再装舵盘，保持通电
  • 舵盘插最接近的一格，残差留给标定
  • 左右腿镜像装配 —— 方向差收进标定表，不改公式
  • 装完立刻测 ±45° 并回填

每次上机前

  • 先发脉宽再使能，机身先垫高
  • 看电压：低于 6.4V 不要开始
  • 状态行盯电流：吸附后要回落
  • 使能中手不进关节活动范围

10换成别的类型会怎样

把第 3 节那些类型放回这台机器上，先摆一条谁都绕不过去的硬约束：

重量这一关先筛一遍

整机重量硬上限 2.5kg，而 18 个舵机是全机最大的一块重量—— 单腿（3 个舵机 + 打印件）实测 260g，六条腿就是 1.56kg，占了无吸附整机预算的八成。

所以"换个更强的执行器"这条路，先被重量否掉一半选项，剩下的才轮到谈钱和谈接口。

Feetech / Dynamixel		 本项目真正值得考虑的那一个。能读回位置、电流、温度，第 6 节那五条坑里有四条会轻松很多； "零力交接"可以直接发力矩指令，不必再绕道位置指令去间接改力。 重量和标准舵机同一个级别，重量这关能过。 代价是接线从 18 路 PWM 变成菊花链、驱动层要重写、供电档位可能要跟着调 值得

修正本页早先的一句话。之前写总线舵机"贵 2~4 倍"——那是拿 Dynamixel 那一档比的。 国产总线舵机在同扭矩档上只贵一点，18 个的差价没有想象中吓人。 真正的成本不在钱，在重做驱动层和线束：串口协议、菊花链供电、ID 分配、掉线处理，都要自己搭一遍。

结论

先用 PWM 数字舵机把机器做出来，仍然是对的选择——便宜、生态成熟、坏了随时换， 而且这台机器的结构件、驱动板、整套开源方案都是围着它设计的。

但要清楚自己买到的是什么：一个便宜、有力、完全不汇报情况的执行器。 本页里所有"实测回填""判据靠气压和电流、不靠指令位置"的做法，都是在给这个盲区打补丁。 等到要做力控或者更精细的步态，第一个该考虑的升级是总线舵机，而不是 FOC 模组。
