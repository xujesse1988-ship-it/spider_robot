## 1. 核心几何规律（本线最重要的结论）

吸盘轴**永远在腿平面内**，coxa 只能整体旋转这个平面。能不能对正一个面，取决于
腿平面是否包含该面的法线：

| | 面外倾角公式 | 说明 |
|---|---|---|
| 地面足 | asin(sinφ · \|sinβ\|) | φ = 身体俯仰，β = 腿平面相对机身 x 轴的夹角 |
| 墙面足 | asin(cosφ · \|sinβ\|) | |

由此得到各腿的可用窗口（容差 12~15°）：

| 腿 | 对地面正 | 对墙面正 |
|---|---|---|
| 前腿，coxa 内摆 55°（指正前，β=0） | 任何俯仰 | 任何俯仰 |
| 后腿，coxa 后摆 55°（指正后，β=180°） | 任何俯仰 | 几何上 φ≥50°，规划器实为 72.5° |
| 中腿（前摆 45° 也只到 β=45°） | φ ≤ 15~20° | φ ≥ 70~75° |

**所以过渡顺序只能是 前 → 后 → 中**，中腿在 φ∈(20°,70°) 谁都对不正，只能悬空。
`docs/ROADMAP.md` P5 写的"前足→中足→后足"不成立。`docs/CLIMBING-DESIGN.md` §6
那张 2D 可落足带表没错，但它隐含前腿 coxa 已指正前——中性角 55° 时前盘对墙偏
55°，根本吸不上。

**另一条**：倾角只由**髋足距离**（与压深）决定，站位半径 176.6 就是"轴⊥面"的解。
所以挪落点要**绕髋摆**，不能平移——平移会把半径拉长（中腿前移 85 时 176.6→196.0，
倾角 10.6°，卡在 12° 带内侧不被拒但目视明显斜，09-09 实机复现）。

## 4. 实机已确认的事实（09-08 ~ 09-09）

- **coxa ±55° 可以**（前腿指正前、后腿指正后都不撞）。
- **舱体厚度约 35 mm**（髋=femur 轴平面以下），代码保留 40 作余量；舱体前后不超出
  机身框架外廓。
- **`--dry` 干跑**：`1 w` / `3 b` / `h` / `g` 四个动作无碰撞。
- **前伸上举时腿够不到**：`--wall-dist 160` 时模型命令悬停在墙前 15 mm，实际 32 mm，
  短 17 mm。悬停高度 210 与目标一致，**只差离墙方向**。
- **偏差逐腿不同**：`--wall-dist 155 --wall-trim 16` 时 L1 停在玻璃外 15 mm（短 16），
  **R1 已经贴上玻璃**（几乎不差）。所以修正量必须逐腿，全局一个值会把 R1 按进玻璃。
- **L1 启动吸不上 = 橡胶软管折死**（用户查出）。盘压全程 0.0 kPa、压深自动加到 28 仍
  纹丝不动 = 气路不通。软件已排除：同配置下两引擎启动压入目标逐腿位数级相同、
  整段启动 545 拍 18 路脉宽零差异。**过渡会把腿摆到从没用过的姿态，软管走线只按
  走路/贴墙爬验证过——上墙前务必用 `--dry` 逐姿态查六条管。**
- **机身弹性下沉（最严重）**：机身前缘中点高度——L1 抬起并吸住墙面后降 **6 mm**
  （吸住后没回来）；再抬起 R1 悬停时又降 **26 mm**；**R1 落下吸住后不回弹**，累计
  **32 mm**。对照前腿可落足带只有 30 mm（该次日志 200~230）。
  ⚠ 这组数是**中腿还在默认站位**时测的；09-11 A 组把中腿先摆到前髋底下重测，见下。
- **`--dry` 六阀长通发热严重**（≈25 W），已改按需排气。
- **中腿绕髋摆到前髋底下后，吸盘轴目视明显斜**（平移版的锅，已改摆动版，未复测）。
- **地面摆动时吸盘蹭玻璃地板**，15 mm 抬离量不够（已改 45 mm，未复测）。
- **上墙过程中中腿吸盘吸不住地面，但压着能靠摩擦当支撑**。

### 4.1 09-11 A 组（基线，不开交接）：中腿前移之后的下沉

机身前缘中点离地高度，单位 mm。参数 `--no-tank --wall-dist 155 --floor-clear 45
--support-legs L2,R2 --wall-trim L1:16,R1:0`：

| 记号 | 时刻 | 高度 | 该步变化 | 09-09 同一步 |
|---|---|---|---|---|
| H0 | 六足吸住（基准） | 143 | — | — |
| H1 | `2 t i` / `5 t i` 中腿摆到前髋底下 | 143 | **0** | 未做 |
| H2 | L1 上墙吸住 | 134 | **−9** | −6 |
| H3 | R1 悬停（未落） | 119 | **−15** | −26 |
| H4 | R1 落下吸住 | 119 | **0（不回弹）** | 不回弹 |
| | 累计 | | **−24** | −32 |

三条结论：

1. **`t` 键（中腿摆到前髋底下）有效**：抬第二只前足的下沉 **26 → 15 mm**，砍掉四成。
   而且中腿自己前移不掉高度（H1 = H0），这一步是白赚的。
2. **不回弹再次确认**：H4 = H3，15 mm 一毫米不还。所以它不是悬空瞬态，是**每换一次
   前足就留下 15 mm**。
3. **`]` 预抬的指令实现率 ≈ 100%，但只有 15 mm 可用**：按 3 次（命令 +15）实际升
   15 mm，**第 4 次被引擎拒绝**——拒绝原因是 `L1 吸盘倾角 16°（面外 0°）超 15°`，
   即**天花板由墙面腿的吸盘倾角容差定**，与仿真逐字复现（同一条信息、同一个高
   110）。⚠ `]` 升机身与 `z` 接管在身体系里是**同一个方向**（都把 L1 的足端指令
   往下推），吃的是同一份倾角预算——两者不能各按各的。项目旧口径"指令位移只有约 42% 被实现"在这里**不
   适用**——那个数来自墙上行走/倾身（切向：吸盘剪切 + 腿链弯曲），而机身竖直升降是
   沿腿的压缩方向顶着刚性地面，几乎不打折。⚠ 可用量 15 mm 与要补的 15 mm 正好相等，
   一点余量都没有。
4. **两只前盘最终都吸在离地 200 mm** —— **账已平**（09-11 补问）：该次没给
   `--wall-height`，落点取带中点，而 `--wall-dist 155 --wall-trim L1:16` 下引擎算出
   L1 的带是 **200~215、中点 208**（R1 是 200~230、中点 215）。L1 命令 208 实际落
   200 = **低 8 mm**，与它落地时机身已沉的 9 mm 对得上（几毫米的标定/读数差）。
   R1 那个 200 不是独立读数——是用 `+` 目视调到与 L1 齐平的结果。⇒ **足端落点确实
   跟着机身一起沉，没有第二个未知因素。**
   ⚠ 两条副产品：①`--wall-trim 16` 把 L1 的可落足带从 30 mm 压到 **15 mm**（trim 叠
   进压深，把落点带的两头都吃掉了）；②按中点命令 → 实际落在带的下沿甚至以下
   （208−9 = 199 < 200）。**下次应按"带中点 + 预计沉降"命令，即取带的上沿附近。**

## 5. 代码现状

### 引擎 `software/hexapod/mount.py`（`MountEngine`）

为什么不扩 `ClimbEngine`：后者把"吸附面 = 身体系 z0 平面、压入方向恒为 −z、落点 xy
在身体系"焊死在每个分段里。过渡阶段每条腿各有各的面而且身体要转，硬塞要把 1400 行
稳态爬墙逻辑翻一遍。本引擎只做过渡需要的三件事，吸附状态机（`AdhesionController`）
与黑匣子（`runlog.ClimbWatch`）原样复用。

- 每腿一个接触面 `Surface`（世界系平面，法向指向机器人一侧）：地面 / 墙面 / 空中。
  抬离与压入沿各自面的法向，倾角按三维算（含 coxa 偏摆的面外分量）。
- 单腿跨面挪动：`VENT→LIFT→TRANSFER→HOVER→land()→DESCEND→PRESS→WAIT`，分段语义与
  `ClimbEngine` 一致（先通气再抬且盘压回升门槛、悬停等人确认、慢下探、压入
  `press_delta`、FAULT 加深重试封顶、耗尽/放气超时/漏气挽救超时冻结）。摆动路径是
  世界系弧线，满弧→半弧→直线三档回退。
- 身体位姿 `(xb, zb, pitch)` 铺设 2°/s、10 mm/s：接触足在世界系钉死、悬空足随身体；
  整段按 1°/5 mm 采样预检（IK 余量 / 关节行程 / coxa 偏摆 / 保持倾角 15° / 膝与机身
  腹面不撞面），任一不过**整段拒绝原地不动**。
- **零力交接（`HANDOVER`）与接管（`TAKEOVER`）**（09-11 加，默认关，见下）。
- 坐标：世界系 地面 z=0、墙面 x=0（机器人在 x<0 侧、头朝墙 +x）、y 左；身体系 x 前
  y 左 z 上；俯仰抬头为正。
- 不做：步态 / 连续行走 / 下滑补偿 / 双足。

#### 零力交接与接管（09-11，`docs/HANDOVER-DESIGN.md` §11 是完整口径）

抬腿前把这条腿的力卸到零、其余接触腿按份额接住（`HANDOVER`）；落地吸住后反向
做一次，把载荷转给刚吸上的新腿（`TAKEOVER`）。每条腿一个世界竖直方向的指令偏移
`ho_off`，六腿偏移代数和恒为 0 ⇒ 身体指令不动（吸住的脚不能滑 ⇒ 改指令=改力）。

- **方向是世界竖直，不是接触面法向**（本文早先那句说反了一半）：地面足的竖直
  恰好是法向（等价于改压深），墙面足的竖直是**切向**——沿墙下滑吃剪切，正是
  climb 里"沿下坡"的那个方向。往墙里压一点根本接不了体重。
- **接管为什么必须有**：climb 靠六腿轮转把偏移还清，过渡的 34 个单腿动作**不
  轮转**（中腿能连着十几个动作不抬），份额只进不出，几次就把压深余量吃穿。
- **接管为什么值得多给**（`--takeover` 大于欠账）：L1 刚吸上墙时是零预载的新腿，
  机身重量还压在被压弯的地面腿里；主动把载荷转给它 = 就地卸掉那些腿攒的弹性
  势能，下一条腿（R1）再抬时储能小、下沉也小。脚本 `z` 键现场每按 3mm 地加。
- **余量**：地面腿的份额/接管量直接变成压深，只有 `PRESS_DEPTH_MAX − press_delta`
  = **10mm**（默认 press 18；要更大就调小 `--press-delta`）；墙面腿不吃压深，
  实算能到 **~27mm** 才被吸盘倾角 15° 咬住——L1 正好是最需要它的那条腿。
- **拒绝口径**：抬腿前的交接塞不下就**拒绝整条挪腿命令**（半截交接比不交接更
  糟）；落地后的接管拒绝不了（腿已经落了），改成二分求最大可行量、截断留痕。
- ⚠ **地面足的卸载方向就是把吸盘往上拔的方向**：δ 超过真实储能会把盘直接拔下来
  （盘压回升→漏气挽救）。墙面上过冲只是反向预载，地面上是真拔。宁欠勿过。
- 保留 climb 的全部安全口径：漏气挽救期暂停铺设（量不丢）、交接腿自身漏气一并
  监护、放气前复检抬腿门槛并超时冻结、解冻不取消在途交接、逐 tick 包络越界截断。

关键可调项与成因：

| 项 | 值 | 为什么 |
|---|---|---|
| `wall_trim`（逐腿） | L1≈16、R1≈0 待重标 | 腿在前伸上举姿态实际到达比模型短，逐腿不同 |
| `floor_clear` | 45 mm | 地面抬离；墙面仍用 `lift_clearance`=15（法向无重力分量） |
| `support_only` | L2/R2 | 只承重不吸附，不参与互锁与漏气监护 |
| `attach_order` | 默认窗序 | 可把可疑腿排最后当反力座诊断 |
| `COXA_MAX_DEG` | 60 | 实机确认 ±55° 可行 |
| `BELLY_MM` | 40 | 实测约 35，留余量 |
| `handover_mm`（逐腿） | 0=关 | 抬腿前卸载量 δ；起标只能先照搬墙上那张表×0.8，过渡工况一个实测值都没有 |
| `takeover`（逐腿） | 0=只还欠账 | 落地后主动接管的载荷；L1/R1 上墙后最该给 |
| `handover_rate_mms` | 10 | 铺设速率，与 climb 同一个 config 字段 |

⚠ `wall_trim` **叠进压入深度**：给大了等于命令腿往刚性玻璃里压 `press_delta+trim`
（吸不上还自动加深到 +10），全变成舵机堵转顶玻璃。宁可给小的。

### 实验脚本 `software/scripts/mount_wall.py`

启动流程与 `body_lean` 同口径（蹲姿预置 → 4 s 竖直站起 → 就位暂停 → 逐足压入吸附）。
黑匣子 tag=`mount`，退出/取机序列从 `body_lean` 复制（改那边记得同步）。

| 键 | 作用 |
|---|---|
| `1`~`6` | 选腿（1=L1 2=L2 3=L3 4=R1 5=R2 6=R3） |
| `w` | 选中腿 → 墙面（墙前 15 mm 悬停，`i` 压入） |
| `g` | → 地面站位回位 |
| `b` | → 地面、髋正后方 `--rear-dist`（缺省=站位半径≈176） |
| `t` | → 绕髋**摆**到地面站位前方 `--fwd-dist`（默认 85） |
| `h` | 收起悬空（不承载，互锁不算它） |
| `i` | 悬停腿落下压入吸附 |
| `z` | 把 `--takeover-step`（默认 3mm）的载荷**接管**到选中的接触腿身上（可连按累加）：其余接触腿各松 3/n，身体指令不动。L1 上墙吸住后就用它把势能转过去 |
| `.` `,` | 悬停中调该腿离墙距离 ±2 mm（= 逐腿 `wall_trim`） |
| `+` `-` | 悬停中沿墙挪该腿落点高度 ±5 mm（20 mm/s 铺设，铺完才许 `i`） |
| `↑` `↓` | 俯仰 ±`--pitch-step` |
| `←` `→` | 身体离墙 / 贴墙 5 mm |
| `[` `]` | 身体降 / 升 5 mm |
| 空格 | 取消位姿铺设 |
| `f` | 解冻 　`o`×2 取机 　`ESC`×2 退出 |
| `d` | **就位暂停专用**：按卷尺实测值改前髋距墙（站起后量才准） |

## 6. 下一步：三个实机测量（决定扶梯路线存废）

推荐命令：

```bash
# A 组（基线，与 09-09 那次同参数）
python scripts/mount_wall.py --no-tank --wall-dist 155 \
    --support-legs L2,R2 --floor-clear 45 --wall-trim L1:16,R1:0

# B 组（开零力交接 + 接管；δ 起标只能先照搬墙上那张表×0.8，逐次加）
# ⚠ 与 A 组一字不差，只多了交接三参数——两组要可比
python scripts/mount_wall.py --no-tank --wall-dist 155 \
    --support-legs L2,R2 --floor-clear 45 --wall-trim L1:16,R1:0 \
    --handover L1:10,R1:10,L3:8,R3:8,L2:5,R2:5 --takeover L1:10,R1:10
```

⚠ **实机前必修的 bug（09-11 仿真发现，已修）**：压深上限原先按绝对值判，而 L1 带
`--wall-trim 16` 上墙后命令压深 18+16 = 34 本就超 28——墙面腿的交接是沿墙切向、
压深一毫米都不动，绝对值判会拒掉一个根本不改这个量的动作，**L1 一上墙，抬 R1 的
交接就被整条拒绝，B 组恰好死在要测的那一步**。改成相对判（只拦"推得更糟"的动作）
后同参数的 B 组全流程在仿真里跑通，回归测试
`test_over_cap_leg_can_still_share_load_but_never_goes_deeper` 入册。跑 B 组前
先 `git pull`。

按这套参数仿真算出来的余量：L1 上墙吸住并自动接管 10 mm 之后，**手动 `z` 还剩
≈ 8 mm（约 3 次）**；落点若取带上沿 215 而不是中点 208，余量涨到 ≈ 26 mm——
**落点高低直接决定你能往 L1 身上转多少载荷**。

⚠ **但 B 组第一遍不要动落点**（不给 `--wall-height`、`--wall-trim` 保持 16）：两组
要可比。"取带上沿补偿沉降"是 A 组那种**不开交接**的跑法才需要的——交接若有效、
机身不沉，落点自己就回带里了，再补反而顶到带的上边缘；而且头号指标 H3−H2 是
R1 悬停时量的，那会儿 R1 还没落地，落点高度不影响它。想多要 `z` 的余量，等可比的
第一遍跑完，再单独跑一遍落点取 215 的。

**上墙前先用 `--dry` 把六条腿的极限姿态过一遍看软管**（`1 w` / `4 w` / `3 b` /
`6 b` / `2 h` / `5 h`），09-09 的教训。

1. ~~中腿摆到前髋底下后，抬 R1 还沉多少~~ **09-11 A 组已做：15 mm（原 26），不回弹**（§4.1）。
2. ~~按 `]` 时命令了多少、实际抬起多少~~ **已做：命令 15 实升 15（≈100%），第 4 次被拒，
   可用量只有 15 mm**（§4.1）。
3. ~~L1、R1 最终吸在玻璃上的实际离地高度~~ **已做：两盘都在离地 200 mm 且齐平**；
   与沉降账对不上的那笔见 §4.1 第 4 条，补齐后再按实际重跑 `tools/mount_plan.py`。
4. **还没做的：B 组（开零力交接）**——命令见上，动作与量点跟 A 组一字不差。
4. **零力交接 A/B（09-11 新增，与 1 合并做）**：同一组动作跑 A（不开）和 B（开）各
   一遍，每步量机身前缘高度。B 组里 L1 吸住墙面后先按几次 `z`（每次 3mm），每按一次
   记一遍高度/盘压/电流——这是"把势能转移给 L1"到底有没有用的直接读数。
   ⚠ **头一次开交接，先拿一条后腿做原地抬落探底**（`3 g` 看住了再 `i`）：地面足的
   卸载方向就是把盘往上拔的方向，δ 过头会把盘直接拔下来（盘压回升 → 漏气挽救，
   安全但要认得出来——状态行该腿由 `·A` 变 `!`、盘差变浅）。⚠ **别拿中腿试**：
   中腿是 `--support-legs`，根本没吸住地面（没真空），卸载只是把腿抬一点，拔盘这个
   风险在它们身上试不出来。后腿抬起时其余五足撑着，是序列里最安全的探底动作；
   它过了再做 `1 w`（那是第一个"吸住地面的腿被卸载"的正式动作）。

判据（**09-11 按 A 组数据收紧**）：原先写的"掉到十几毫米以内就算可走"不成立——A 组
的 15 mm 是**留下的**（H4 = H3，不回弹），扶梯 9 对换脚每次留 15 mm 就是 135 mm，
照样是"上百毫米漂移"。所以要看的是**每换一次前足留下多少**：

- 留下的量压到**个位数** → 扶梯路线可走（9 次累计几十毫米，靠每次换脚重新对位兜得住）。
- 仍留十几二十毫米 → 扶梯路线要重做（改成始终保证机身前后各有支撑的走法，或先减重）。
- 交接 A/B：B 组的 H3−H2 显著小于 A 组的 15 mm → 交接对症，接着标 δ 表与接管量；
  两组一样 → 下沉不是"放气瞬间储能释放"这个机理（那就要重新找因，比如舱体/机架
  本身的变形），别再往扶梯路线上投工。
- `z` 接管每按一次：高度涨回去一点 = 势能真转走了；高度不动而整机电流往上爬 =
  只是在互相顶（内应力），停手。
